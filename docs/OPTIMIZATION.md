# 运行时优化记录

目标：在保持原有硬直分级、恢复、衔接和动画通知时序的前提下，减少每次事件的引擎调用、字符串驻留、JSON 解析和容器分配。基线是迁移完成后的 `01ce2f7c68751af4c2875253d7e9f4c2ebd0b0f8`，优化版本为 1.2.1。

## 时序与缓存

| 路径 | 优化 | 保持的执行规则 |
| --- | --- | --- |
| 动画通知 | 先检查事件名和预建恢复事件索引，再进行一次角色类型转换和图查询 | StaggerStart 的方向、等级和特殊转场先于原通知；快速恢复仍先发送原 StaggerStop，再发送原事件 |
| 动画事件 | 六种事件按长度分类，排除无关事件后才转换角色类型 | 普通开始清除特殊 ID；所有六种事件继续写入五个计数器，仅对应计数器累加，其他归零；最后调用原处理函数 |
| 图变量与事件名 | 持有 BSFixedString，复用引擎驻留字符串；DataLoaded 预热 | 只缓存名字，不缓存图变量地址或角色/动画图指针 |
| 配置 | 读取 INI 后生成四个 float 阈值和跳跃开关快照；恢复事件排序去重，8 项以内线性查找，超过 8 项二分查找 | 原项目配置仅在初始化时载入；阈值仍按原来的等级逆序判断，不重新排序阈值 |
| 特殊受击 | 每线程 32 槽内容缓存，保存 JSON 原文副本、解析状态、动画 ID 和 IgnoreStaggerLevel | 每次仍向 Precision 取得当前载荷；按完整字节内容验证命中，不保留外部字符串指针，不缓存角色状态 |
| 转场 | 消除整份转场对象复制；允许列表改为排序、去重的连续 int32 数组和二分查询 | 保持当前 ID 为零、相同 ID、Unrestricted、允许列表的判断顺序及语义 |
| 每帧角色状态 | 复用变量名，继续在原 Update 后读取控制器并同步动画图 | 不降频，不延后落地/战斗事件；动画图重建或其他写入不会被永久缓存遮蔽 |

JSON 缓存按内容共享同一线程内不同角色的相同载荷。不同内容即使落入同一槽也必须完整比较并重新解析；无效 JSON 也缓存失败结果。长度超过 4096 字节的内容正常解析但不驻留，避免长载荷长期占用缓存。线程之间不共享可变缓存，无额外全局锁，也无需维护角色销毁、换档和指针复用清理。

字符串匹配按动画事件使用的 ASCII 大小写规则比较。特殊动画 ID 保留原有 DJB2 32 位结果，改用无符号运算定义溢出行为；空动画名继续表示 ID 零。

## 调度与 CPU 指令

原项目没有自己的任务调度器；更新、动画通知、落地调用均由引擎驱动。优化留在这些同步回调内，以事件过滤降低执行次数。把这些回调改为工作线程或批量延后会改变本次物理/动画更新可见的值，因而没有添加新的异步调度器。

热路径以引擎虚调用、短字符串判断、JSON 和离散状态分支为主；阈值仅四个 float 比较，字符串哈希有逐字节依赖，没有批量浮点乘加任务。这里优先消除解析、分配和复制，并采用连续容器。没有强制启用 `/arch:AVX2`、FMA 或快速浮点运算；避免为了单个小判断提高整个 DLL 的最低 CPU 要求。MSVC 对各指令集选项的定义见 [官方 /arch 文档](https://learn.microsoft.com/en-us/cpp/build/reference/arch-x64?view=msvc-170)。

## 验证方法

`tests/runtime_tests.cpp` 对生产代码进行确定性回归与随机差分测试，覆盖事件分类、大小写、阈值边界/乱序/NaN、哈希、恢复事件以及 JSON 缓存失效、碰撞和长内容路径。测试不依赖启动游戏。

```powershell
cmake -S . -B build/ng-local -DMSL_BUILD_TESTS=ON
cmake --build build/ng-local --config Release --target ModernStaggerLock msl_runtime_tests msl_runtime_bench --parallel 8
ctest --test-dir build/ng-local -C Release --output-on-failure
./build/ng-local/Release/msl_runtime_bench.exe 2822558223
```

基准比较旧算法与当前生产算法，报告同一机器上多轮测量的中位数；它隔离了插件内的计算开销，没有模拟引擎锁、物理更新、图求值或实际战斗负载。实测结果见下表；游戏内帧率和帧时间仍需在相同场景下另测。

机器：Intel Core i5-13600KF；MSVC 19.44 x64 Release；随机种子 2822558223；2 轮预热后测量 7 轮，取中位数。单位为纳秒/次。

| 独立算法场景 | 原算法 | 优化后 | 原/新耗时比 |
| --- | ---: | ---: | ---: |
| 六种已支持事件分类 | 55.16 | 17.56 | 3.14× |
| 无关事件过滤 | 12.88 | 1.51 | 8.53× |
| 相关/无关混合事件 | 21.56 | 9.69 | 2.23× |
| JSON 直接解析 / 8 个热载荷缓存命中 | 1013.11 | 43.81 | 23.12× |
| 32 项转场列表，复制 string+set / 引用 vector | 830.28 | 4.13 | 200.82× |
| JSON 128 种载荷轮换 / 32 缓存槽 | 625.68 | 639.56 | 0.98× |
| 4 项恢复事件 | 20.57 | 18.61 | 1.11× |
| 32 项恢复事件 | 138.99 | 49.59 | 2.80× |
| 256 项恢复事件 | 1012.97 | 78.80 | 12.85× |

转场的较大倍数来自消除原先每次查询复制 32 个树节点的开销，数值只适用于这个独立操作。缓存收益取决于内容重复率；128 种载荷轮换的测量约增加 2.2% 开销。小恢复列表的首次二分实现也出现退步，因而改成了上述混合策略。原始测量见 [基准输出](audit/runtime-bench-1.2.1.txt)。
