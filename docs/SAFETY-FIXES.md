# 1.2.2 安全修复

## 范围与需求

基线：`c1317ceec4203edf33e0bd36087a128891c8a80f`（1.2.1）。用户要求检查 `E:/source/repos/Precision-main`，并修复上一轮 ModernStaggerLock 审计中其余 P2/P3。本次修复初始化发布、计数器溢出和 JSON 资源上限；保留游戏版本、Hook 地址、回调原函数调用顺序和常规大小输入的行为。

Precision 源码只读核查，结论见 [PRECISION-AUDIT.md](PRECISION-AUDIT.md)。本次不把标准 Precision 改造成 V5 分支，也不修改其 API 或源码。

## 初始化发布

`MSLSettings` 使用原子 ready 标志。`kPostLoad` 仍安装 Hook 和请求外部接口；`kDataLoaded` 完成设置 singleton 与固定字符串初始化后，才用 release 发布 ready。

所有会访问插件运行时数据的 Hook 先 acquire 读取 ready：动画通知、动画事件、跳跃、NPC/玩家 Update 和落地处理。在未 ready 时跳过插件处理，并继续调用游戏原函数；不会在 Hook 中等待初始化或触发配置读取。特殊硬直数据入口也检查 ready。

这使先前写入的 Precision 接口、恢复事件集合和配置快照先于后续读取发生。发布之后这些数据保持只读；本版本不提供运行期配置重载。

## 计数器

通过 `Logic::NextCounter` 在无符号 32 位表示上递增，再位转换回有符号值。`INT_MAX` 明确定义为转到 `INT_MIN`，`-1` 转到 `0`。该策略让计数值继续变化，保留原机器上的环绕行为，不采用会在上限停止变化的饱和策略。

计数器仍在每次相应事件中写齐五项，普通开始事件仍清除特殊硬直 ID；原通知顺序不变。

## JSON 输入与内存

| 输入 | 上限与处理 |
| --- | --- |
| Precision 运行时载荷 | 最多 64 KiB，超限直接返回失败，不建立 JSON DOM |
| 原始 C 字符串 | 最多检查 64 KiB + 1 字节以寻找 NUL，不先调用无界 `strlen` |
| 解析缓存 | 仍为每线程 32 槽，最多缓存 4096 字节的 key；4097..65536 字节载荷允许解析但不缓存 |
| JSON 配置单文件 | 最多 4 MiB；实际分块读取并最多额外读 1 字节检查超限，不仅依赖可变化的文件大小元数据 |
| 累计配置内容 | 本次初始化最多把 16 MiB 内容送入 JSON 解析；无效 JSON 也扣除已读取字节 |

运行时解析和缓存的分配失败返回 false，输出对象保持原值。配置读取失败或超限会记录错误并跳过文件；解析时遇到内存分配失败会停止处理后续文件。原有 JSON 错误日志保留。

上限约束的是输入字节，不是 JSON DOM 的精确堆占用：节点、字符串和容器仍有分配开销。缓存仍按调用线程分别持有，也不代表进程统一的 128 KiB 内存上限。

借用字符串仍必须由提供方保证读取期间有效；有界扫描不检查悬空指针，也不能替代 Precision 的所有权契约。标准 Precision 2.0.6 不含该 V5 路径。

## 兼容性与验证

事件 Hook 参数补齐 `const RE::BSAnimationGraphEvent*`，与 CommonLib 声明一致；虚表槽位、落地补丁、硬直分支地址和最低 SKSE 版本均未改变。

验证包含 MSVC x64 Release 构建、独立回归测试、ASan + UBSan，以及最终 DLL 的导出/版本信息与安装包完整性检查。回归新增计数器环绕、载荷上限、C 字符串有界扫描和实际配置读取函数的边界测试；保留原随机差分测试。

没有运行游戏内战斗和真实线程竞态复现；sanitizer 独立测试不访问 Skyrim 对象，也不代表对整个游戏进程做了内存检测。
